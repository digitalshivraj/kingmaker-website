On the day before the CEO's review meeting, the same scene plays out in many Zilla Parishad departments, whether in Jalgaon, Solapur or Amravati. A clerk phones each block office for figures, copies them into a spreadsheet, fixes the Marathi font and prints the statement for the file.

By the time it reaches the table, two blocks have sent last month's numbers and the clerk's own files have waited. The report itself is not the problem. The compiling is.

## Enter the data once, where the work happens

A report should be a by-product of daily work, not a separate task. The gram sevak updates a beneficiary's stage on a phone. The desk clerk marks a file received and forwarded. The head teacher marks attendance. Each fact is **entered once, at the source**, by the person who actually knows it.

After that, every report is only a different view of the same data: block-wise for the block development officer (BDO), department-wise for the head, district-wise for the CEO. Nobody retypes anything, so the figures in two reports cannot disagree. When a number looks wrong, you can see who entered it and when, instead of asking three offices over the phone.

The clerk who used to compile gets that time back for the pending files.

## The five reports worth automating

Most departments can start with these.

1. Scheme beneficiary progress: for each scheme, how many applications are received, sanctioned, started, completed and paid, block by block. The useful part is the exception list, showing beneficiaries stuck longest at one stage and the block they belong to.
2. Pending files by desk: every [inward entry, the desk it sits on](/blog/inward-outward-register-software/) now, and how many days it has been there. The department head sees the oldest files first, not just a total.
3. Field visit records: which officer visited which school, anganwadi, health centre or work site, with date, photo, phone location and remarks. The report also lists places nobody has visited this month.
4. School or health centre attendance: staff present, on leave and absent, institution by institution, plus the institutions that have not reported today. For education it can include student attendance. For health, it covers the staff at each primary health centre and sub-centre.
5. Fund utilisation: for each scheme head, funds received, sanctioned, spent and balance, by block, with utilisation statements still pending. Confirm the exact heads and formats with your accounts and finance department before the report is fixed.

Each report answers the question an officer asks in every review: where is it stuck, and with whom?

## Marathi formats officers already use

Officers trust the prapatra they have signed for years. An automatic report should look like that statement: the same columns in the same order, the same Marathi headings, the same totals row. If the department sends a monthly statement upward in a set format, the system should produce that exact format, not a new dashboard that someone must then copy from.

Two details matter in practice. The report should be in **Unicode Marathi**, so it opens correctly on any phone without a special font. And it should come as a PDF for the file and a spreadsheet for officers who want to work with the numbers. This kind of formatted output is what our [data and document systems](/services/data-document-systems/) work covers. Where the state prescribes a format, confirm the current version with the department.

## On WhatsApp and email each morning

A report that waits inside a login is a report nobody opens. So send it where officers already look. Each morning, before the office fills up, the officer gets a short WhatsApp message in Marathi: three or four lines on what moved, what is stuck and which blocks have not reported, with the PDF attached. The full statement goes by email for the record.

Each officer gets their own level. The BDO gets the block. The department head gets the department. The CEO gets a **one-page district summary** across departments.

Two cautions. Send through the [official WhatsApp Business API](/blog/whatsapp-business-api-vs-tools/), not a personal number or a group, which is how our [WhatsApp automation](/services/whatsapp-automation/) is built. And keep beneficiary names and personal details inside the login. The message should carry counts and exceptions only.

## Where a department can start

You do not need all five at once. A sensible order:

- Pick the one report that costs the most effort today, often pending files or one large scheme.
- Collect the current Marathi format and list who knows each fact first.
- Give those people a simple entry screen on their phones.
- Run the automatic report beside the manual one until the figures match and officers trust it.
- Stop the manual report, then add the next one.

## Common questions

### Do block and field staff need computers?

No. Entry can be done on an ordinary Android phone, in Marathi, on screens designed for weak networks. A computer helps only at desks that handle many files a day.

### What if a block does not enter its data?

The report shows that block as not reported. It does not carry an old figure forward, so the gap is visible to the BDO and the department head that same morning.
